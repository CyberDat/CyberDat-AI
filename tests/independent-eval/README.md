# Независимая оценка четырёх инструментов: инструкция для владельца

Все цифры в отчётах до сих пор получены на наборах, которые написал автор правил (Claude Code). Они **не независимые** и завышены. Независимая оценка возможна только на ваших данных. Ниже описано, как их подготовить и проверить локально. Ничего никуда не отправляется.

## Что подготовить: 5–10 образцов на инструмент

| Инструмент | Файл-шаблон | Что взять | Разметка |
|---|---|---|---|
| Log Anonymizer | `templates/log-anonymizer.json` | Фрагменты реальных логов: nginx/Apache, auth.log, JSON приложений, CloudTrail, Windows Event | `mustMask`: значения, которые должны исчезнуть (IP, логины, почты, токены). `mustKeep`: контекст, который должен остаться (URL-пути, версии, коды ответов) |
| Prompt Injection Detector | `templates/prompt-injection-detector.json` | Тексты, которые попадают к ассистенту: веб-страницы, письма, README, тикеты. Примерно поровну атак и обычных текстов | `label`: `attack` или `benign` |
| LotL Analyzer | `templates/lotl-command-analyzer.json` | Командные строки из EDR или Sysmon: подтверждённые инциденты и обычная администраторская активность (SCCM, GPO, скрипты IT) | `label`: `malicious` (только подтверждённые расследованием) или `benign` |
| MCP Checker | `templates/mcp-security-checker.json` | Реальные `claude_desktop_config.json`, `.mcp.json`, `.vscode/mcp.json`, выводы `tools/list` | `label`: `risky` или `benign`; можно указать `expectGroups` |

Правила разметки:

- **Размечайте до запуска инструмента.** Иначе разметка подстроится под результат.
- Добавляйте и сложные обычные случаи: внутренние шары, `ignore` в обычном тексте, конфигурации с `npx`.
- В поле `source` коротко опишите происхождение (откуда взят образец), без персональных данных.
- В каждом файле укажите `"provenance": "owner"` и `"authoredByToolAuthor": false`. Только тогда скрипт пометит результат как INDEPENDENT.

## Секреты и персональные данные удаляйте вручную до сохранения файла

- Ключи, токены, пароли и cookie замените на вымышленные значения **той же формы** (например, `ghp_` + 36 символов `X`) или на ссылки вида `${env:NAME}`. Настоящие секреты в файл не попадают никогда.
- Реальные домены компании, внешние IP, имена и почты сотрудников заменяйте последовательно: одно реальное значение — одна замена. Используйте `example.com`, `203.0.113.x`, `alice`.
- Не используйте сам Log Anonymizer для очистки набора Log Anonymizer: так вы проверите инструмент им же.

## Где хранить и как запустить

- Файлы с реальными данными храните **вне репозитория** или в `tests/independent-eval/data/`. Эта папка и файлы `*.owner.json` исключены из git через `.gitignore` в этой папке. Перед коммитом всё равно проверьте `git status`.
- Запуск (локально, офлайн):

```
node tests/independent-eval/evaluate.cjs <путь>/lotl.owner.json <путь>/mcp.owner.json --details
```

- Скрипт печатает только id образцов, метки и счётчики, сам текст образцов не выводится. Порог по умолчанию — `medium`, его можно поменять полем `threshold`.
- Метрики: detection — доля найденных положительных образцов; false positives — доля отрицательных образцов, на которых сработал порог (для Log Anonymizer — изменённый `mustKeep`).

## Как использовать результаты

- Пришлите только сводку (detection, false positives, id промахов), без самих образцов.
- Правки по промахам из независимого набора делаются на **новых** примерах. Независимый набор после этого считается использованным: для следующей оценки нужен новый.
